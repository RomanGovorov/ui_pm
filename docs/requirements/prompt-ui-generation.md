# Шаблон промпта для генерации UI Project Manager

## Промпт

Создай веб-приложение для визуализации состояния проектов. Это интерфейс для AI-агента project-manager, который ведёт задачи и показывает их стейкхолдерам.

### Контекст

AI-агент `project-manager` автоматически управляет проектами: создаёт задачи, ведёт бэклог, меняет статусы. Стейкхолдеры и руководители должны видеть состояние проекта в реальном времени через веб-интерфейс, похожий на Jira.

### Технический стек

- **Frontend:** Next.js 14+ (App Router)
- **Backend:** Next.js API Routes
- **Database:** PostgreSQL + Prisma ORM
- **Real-time:** WebSocket или Server-Sent Events (SSE)
- **Styling:** Tailwind CSS
- **UI компоненты:** shadcn/ui или аналогичная библиотека

### Визуальные требования

- **Тема:** тёмная тема по умолчанию, переключение на светлую
- **Стиль:** минималистичный, похожий на Jira
- **Адаптация:** десктопный браузер (мобильная версия не требуется для v1)

### Структура интерфейса

#### 1. Боковая навигация (Sidebar)

- Список проектов (5-10 проектов)
- Кнопка "Создать проект"
- Переключатель темы (тёмная/светлая)
- Активный проект выделен

#### 2. Дашборд (основная область)

**Канбан-доска с тремя колонками:**

| In Work | Review | Done |
|---------|--------|------|
| Карточка задачи 1 | Карточка задачи 3 | Карточка задачи 5 |
| Карточка задачи 2 | Карточка задачи 4 | Карточка задачи 6 |

**Карточка задачи содержит:**
- Название задачи (обязательно)
- Приоритет: High / Medium / Low (цветовой индикатор)
- Ответственный (имя или аватар)
- Дата последнего обновления
- Краткое описание (опционально, обрезается до 2 строк)

#### 3. Шапка (Header)

- Название текущего проекта
- Селектор подпроекта (если есть)
- Кнопка "Создать задачу"
- Индикатор подключения (online/offline для real-time)

### Сущности и поля

#### Project (Проект)
```
id: UUID
name: string
description: string (optional)
created_at: datetime
updated_at: datetime
```

#### Subproject (Подпроект) — опционально
```
id: UUID
project_id: UUID (FK)
name: string
description: string (optional)
```

#### Task (Задача)
```
id: UUID
project_id: UUID (FK)
subproject_id: UUID (FK, nullable)
title: string
description: text (optional)
status: enum ('in_work', 'review', 'done')
priority: enum ('high', 'medium', 'low')
assignee: string (имя ответственного)
created_at: datetime
updated_at: datetime
```

#### User (Пользователь) — для v1 минимально
```
id: UUID
name: string
role: enum ('stakeholder', 'agent')
```

### Функциональные требования

#### UI (для стейкхолдеров)

1. **Просмотр канбан-доски**
   - Отображение задач в трёх колонках по статусу
   - Автоматическое обновление при изменении статуса (real-time)
   - Переключение между проектами через боковую навигацию

2. **Создание задачи** (опционально для v1, но желательно)
   - Модальное окно с формой
   - Поля: название, описание, приоритет, ответственный, проект

3. **Переключение темы**
   - Тёмная/светлая тема
   - Сохранение выбора в localStorage

#### API (для агента)

Реализовать REST API эндпоинты:

```
GET    /api/projects              — список проектов
POST   /api/projects              — создать проект
GET    /api/projects/:id          — получить проект
PUT    /api/projects/:id          — обновить проект
DELETE /api/projects/:id          — удалить проект

GET    /api/projects/:id/tasks    — список задач проекта
POST   /api/tasks                 — создать задачу
GET    /api/tasks/:id             — получить задачу
PUT    /api/tasks/:id             — обновить задачу (включая смену статуса)
DELETE /api/tasks/:id             — удалить задачу

GET    /api/users                 — список пользователей
POST   /api/users                 — создать пользователя
```

**Аутентификация API:** без авторизации для v1 (открытый доступ).

#### Real-time обновления

- При создании/обновлении задачи через API все подключённые клиенты получают обновление
- Использовать WebSocket или SSE
- Индикатор подключения в шапке (online/offline)

### Примеры данных для демо

Создать мок-данные для демонстрации:

**Проекты:**
1. "Разработка мобильного приложения"
2. "Редизайн сайта"
3. "Интеграция с CRM"

**Задачи (для проекта "Разработка мобильного приложения"):**

In Work:
- "Реализовать экран авторизации" (High, Иван Иванов)
- "Настроить CI/CD" (Medium, Пётр Петров)

Review:
- "Сверстать главный экран" (Medium, Анна Сидорова)
- "Написать unit-тесты для API" (Low, Сергей Николаев)

Done:
- "Спроектировать базу данных" (High, Иван Иванов)
- "Настроить репозиторий" (Low, Пётр Петров)

### Критерии приёмки

- [ ] Дашборд отображается с тёмной темой по умолчанию
- [ ] Канбан-доска показывает три колонки: In Work, Review, Done
- [ ] Карточки задач отображают название, приоритет, ответственного, дату
- [ ] Боковая навигация показывает список проектов
- [ ] Переключение между проектами работает
- [ ] При создании задачи через API она появляется на доске без перезагрузки
- [ ] При изменении статуса задачи карточка перемещается в нужную колонку в реальном времени
- [ ] Переключатель темы работает (тёмная ↔ светлая)
- [ ] API документирован (OpenAPI/Swagger или README с примерами)

### Что НЕ нужно делать

- Уведомления (email, push, Slack)
- Детальная аналитика и отчёты
- Drag-and-drop карточек между колонками (агент управляет статусами через API)
- Фильтры и поиск по задачам
- Интеграции с Jira / GitHub / GitLab
- Мобильная адаптация
- Авторизация пользователей

### Дополнительные указания

- Код должен быть чистым, с комментариями на английском
- Использовать TypeScript строго
- Следовать best practices Next.js 14 (App Router, Server Components где возможно)
- Prisma schema должна соответствовать описанным сущностям
- API эндпоинты должны возвращать JSON в формате REST
- Обработка ошибок: возвращать понятные сообщения об ошибках

## Использование этого промпта

Этот промпт можно использовать для:

1. **Генерации через AI-инструменты:** v0.dev, bolt.new, Cursor, Qwen Code
2. **Передачи разработчику:** как техническое задание для фронтенд-разработчика
3. **Создания прототипа:** начать с мок-данных, потом подключить реальную базу

**Рекомендуемый порядок работы:**

1. Сгенерировать UI с мок-данными (без базы)
2. Подключить PostgreSQL + Prisma
3. Реализовать API эндпоинты
4. Добавить real-time обновления (WebSocket/SSE)
5. Протестировать с агентом project-manager
